# Conformance vectors

Generated by `python3 action_receipt.py --regenerate`. Do not edit by hand.

- 222 vectors: 58 positive, 147 negative, 17 configuration (`ERROR`).
- 16 reject reason codes, every one exercised.
- Vector set digest: `sha256:403c1d79fa3f5bd0cf4a15eae1790acd7c132b90cb0ac1ea131af4c8729b7a96` (cite this when claiming conformance).
- Every single-fault negative is one mutation of a canonical positive. Its reason is
  the code of the first check that mutation fails under the order of spec §5.
- 17 `neg_order_*` vectors carry two faults in adjacent steps on purpose; the
  earlier step's code is expected, so a verifier that swaps the steps fails them.
- `err_config_*` vectors give the verifier a configuration outside the contract of
  spec §5 (mode, clock, maximum age, paid resource URL); the expected verdict is
  `ERROR` with reason `invalid_configuration`, whatever the receipt.
- Every positive's report is declared by hand in the suite (`EXPECT_REPORT`) and
  compared in full; the manifest publishes the same report.
- `keys.json` is a test fixture standing in for authorization and key resolution.
- ECDSA signatures are deterministic (RFC 6979): `--regenerate` reproduces the files.

## Contexts

| Context | What the verifier holds |
|---|---|
| `ok` | successful settlement with a transaction; accepted requirements held |
| `failed` | `success: false` |
| `batch` | Solana batch-settlement commitment: settlement reference only, no payer |
| `both` | Solana settlement carrying both a transaction and a settlement reference |
| `no_requirements` | accepted requirements NOT held |
| `response_casing` | response `payer` in checksum case, `transaction` in upper-case hex |
| `no_payer` | response carries no `payer` |
| `archival` | archival mode, 180 days after issue |
| `requirements_float_spelling` | accepted requirements spell an integer as `60.0` |
| `requirements_not_object` | what is held as accepted requirements is not a JSON object |
| `payer_empty_string` | response `payer` is the empty string |
| `requirements_other_network` | response `network` is not a network identifier; accepted requirements name another network |
| `paid_this_resource` | the verifier made the payment and paid for this resource |
| `paid_another_resource` | the verifier made the payment and paid for a different resource |
| `advertised_scope_not_a_string` | the advertised `info` held has a `scope` that is not a string |
| `advertised` | the echoed extension `info` is also held |
| `advertised_info_outside_value_domain` | the advertised `info` held contains `1.5`, outside the value domain |
| `session_default_max_age` | session mode with NO `maxAgeSeconds`: the default 3600 applies |
| `session_max_age_100` | session mode, `maxAgeSeconds` 100 |
| `settlement_transaction_only` | only a successful transaction; no network, payer or requirements held |
| `lookalike_network` | network `eip1559:1` (not `eip155:`) with free-form identifiers |
